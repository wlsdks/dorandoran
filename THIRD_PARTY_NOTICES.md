# Third-party licenses and distribution notices

The repository's own [LICENSE](LICENSE) is MIT, copyright 2026 jinan stark (@wlsdks). This does not replace third-party licenses. This audit covers the two npm lockfiles' published licenses, preserved distribution notices, current fonts, and inclusion in the inspected build. Paid service/account contracts are outside this OSS package audit.

The 2026-10-05 snapshot covers both npm lockfiles: **647 package locations / 556 distinct name@version pairs**. All 556 metadata records were checked against the official npm registry, with no declared-license discrepancy. **596 locations are installed**: root 325 (149 production, 176 development-only), functions 271 (all production). Together these are **420 installed production locations / 340 distinct production name@version pairs**. The other 51 lock entries are uninstalled optional platform packages. Classification follows npm's lockfile `dev` flag; an installed production dependency is not necessarily shipped in browser JavaScript.

The authoritative machine inventory is [licenses/inventory.json](licenses/inventory.json). Every entry records its exact version, installation path, registry URL, license selection, original-notice source, SHA-256, and remaining provenance limitations. All inspected items have completed declaration/notice coverage, with publication formats recorded explicitly instead of treating the absence of a separate LICENSE file as an unknown license. Original bytes are stored under [licenses/texts](licenses/texts), with font licenses under [licenses/fonts](licenses/fonts).

## Files shipped with builds

- [public/LICENSE.txt](public/LICENSE.txt) and [functions/LICENSE.txt](functions/LICENSE.txt) include the project's unchanged MIT original in both distribution paths. The offline check validates its reviewed SHA-256.
- [public/THIRD_PARTY_NOTICES.txt](public/THIRD_PARTY_NOTICES.txt) contains the root production dependency closure and both font licenses. Vite copies it to `/THIRD_PARTY_NOTICES.txt` in the hosting artifact.
- [functions/THIRD_PARTY_NOTICES.txt](functions/THIRD_PARTY_NOTICES.txt) contains the server production dependency closure. It lives in the configured `functions` source and is not excluded by `firebase.json`.
- [public/licenses/Inter-v4.1-OFL.txt](public/licenses/Inter-v4.1-OFL.txt) and [public/licenses/Pretendard-v1.3.9-OFL.txt](public/licenses/Pretendard-v1.3.9-OFL.txt) provide separately readable, unchanged font notices.

`npm run licenses:check` is entirely local: it compares lockfile hashes, preserved original-text hashes, the project MIT license hash, the Inter binary hash, and generated notice bytes. It performs no network requests and needs no credentials. `npm run build` runs this check before Vite. `npm run licenses:generate` regenerates the six distribution license/notice files from the reviewed snapshot; it does not refresh an outdated inventory. Dependency changes require a new source/license review and inventory update.

A functions-only checkout can install and run its committed server package without the root application or this root script. Its committed `THIRD_PARTY_NOTICES.txt` remains available in the server source/deployment package. Updating server dependencies requires the full repository's inventory review before producing new notices; root-only verification is not a functions runtime dependency.

## Build evidence and development boundary

A production Vite build was inspected on 2026-10-05 with a `generateBundle` module inventory: 57 JavaScript chunks, 831 contributing modules, and 25 npm package names. Neither Lightning CSS / its native binding nor `caniuse-lite` contributes a browser chunk module. Lottie, JSZip, and Pako are also absent from those current chunks, although they remain in the conservative production-installation notice list. This work does not change their dependency versions or remove them.

No `@license` or `Copyright` comment survived in the generated JavaScript/CSS chunk files, and no automatically emitted license sidecar was present. The explicit static notice output is therefore required for the current build path. The same build contained the notice document, font license files, and pinned Inter WOFF2. This is a build observation, not proof about every future artifact or a previous live deployment.

## Existing assets and remaining provenance limits

Current character SVGs and icon SVG are generated by `scripts/generate-brand-assets.mjs` from the local `src/lib/dorandoran-art.js` source; all six checked SVG files exactly reproduce from that source. `node scripts/generate-brand-assets.mjs --raster` renders the project's icon SVG and existing `tests/og-card.html` into the three PNG icons and JPEG OG image using the installed Playwright Chromium. The four raster outputs reproduced byte-for-byte in two consecutive runs with the same browser version on 2026-10-05; other browser/platform versions may differ in rasterization. No separate externally supplied mascot/illustration is used. Notification sound effects and the Web Audio synthesizer were removed on 2026-10-05; no audio recording is shipped.

There is no current `lottie-react` import, external Lottie JSON URL, or shipped third-party animation JSON under `src` / `public`. Historical Lottie code in `4465c4a` embedded an inline checkmark definition and was replaced by Framer Motion in `49ecd35`; no external LottieFiles source was found in that source history search. The installed player licenses remain inventoried, but a player's MIT license would not establish a separate animation asset's license.

All seven tarballs were downloaded as data, without installing or executing package scripts, and verified against the registry's exact SHA-512 `dist.integrity`. Their declarations agree with the installed lock versions. The four server MIT tarballs contain no separate original LICENSE or copyright sentence in any shipped source/README; this is recorded as **upstream has no separate original notice**, not as a missing or conflicting usage license. npm's official publication documentation directs common-license authors to **“add a current SPDX license identifier”**. We preserve the publishers' exact declarations and author attribution and supply the [unchanged canonical SPDX MIT text](https://spdx.org/licenses/MIT.html). Its example `<year>` / `<copyright holders>` placeholders are intentionally not filled: no dates or copyright statements are reconstructed. The same method preserves the types package's published Apache declaration and author with the project's original Apache terms. [Official npm license-field guidance](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#license)

No package update or override was needed for notice completion. The four server packages come through these SDK dependencies:

- `eastasianwidth`: `firebase-admin@14.5.0 → @google-cloud/firestore@9.3.1 → @google-cloud/firestore-api@0.2.0 → google-gax@5.0.8 → rimraf@5.0.10 → glob@10.5.0 → jackspeak@3.4.3 → @isaacs/cliui@8.0.2 → string-width@5.1.2`. It computes terminal/display string widths for CLI formatting.
- `stream-events`: storage transport via `firebase-admin@14.5.0 → @google-cloud/storage@8.2.0 → teeny-request@11.0.1`, plus the Firestore transport's `google-gax@5.0.8 → retry-request@8.0.4 → teeny-request@10.1.4`. It observes stream read/write calls.
- `stubs`: the preceding `stream-events@1.0.5` dependency wraps/restores stream methods.
- `tr46`: `firebase-admin@14.5.0 → @google-cloud/storage@8.2.0 → gaxios@6.7.1 → node-fetch@2.7.0 → whatwg-url@5.0.0`. It normalizes internationalized domain names for URL parsing.

The application's server entry directly imports Admin `app`, `auth`, and `database`, not Storage or Firestore APIs. These four packages remain in the installed/server distribution closure rather than the browser artifact; no runtime behavior was changed to complete their notices. Forcing an unrelated major `tr46` override could change URL-parser APIs, and replacing SDK transport dependencies merely to add a license file would require transport regression testing. Development paths are `eslint → imurmurhash`, `eslint → @humanfs/node/core → @humanfs/types`, and `vite → rolldown → the platform binding`; they do not ship in the inspected application chunks.
